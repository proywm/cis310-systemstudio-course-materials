# SystemStudio CIS 310 VS Code Extension

This is the accelerated CIS 310 implementation track. It gives students one VS Code entry point for installing, opening, previewing, and testing Digital logic circuits while the broader senior-design project continues in parallel.

## What is implemented

- first-run prompt to install the pinned Digital v0.31 release;
- download to VS Code extension-managed global storage;
- archive and `Digital.jar` SHA-256 verification before use;
- Java 8+ detection with a configurable machine path;
- one-click launch of the full Digital graphical editor for a selected `.dig` file;
- in-editor circuit preview generated by Digital’s own SVG exporter;
- headless execution of embedded Digital test cases;
- VS Code Test Explorer discovery for `.dig` files containing a `Testcase` component;
- a CIS 310 activity-bar view showing Digital, Java, and workspace-trust status;
- a starter-workspace generator with verified upstream half-adder and ALU examples; and
- restricted-mode controls that prevent workspace circuit execution before trust is granted.

## Honest integration boundary

Digital is a Java Swing desktop application. VS Code webviews cannot embed its native graphical window. The extension therefore provides:

1. **inside VS Code:** setup, status, SVG preview, deterministic tests, output, and Test Explorer;
2. **one click from VS Code:** the full Digital graphical editor and interactive simulator, opened on the selected circuit; and
3. **one managed installation:** Digital is downloaded and stored by the extension, so students do not install Digital separately.

Reimplementing Digital’s canvas as a webview is not part of this accelerated MVP. It remains a senior-design workstream if a fully native VS Code circuit editor is still desired.

## Student installation

### Prerequisite

Install Java 8 or newer. Java 17 or 21 is recommended. The extension checks Java but does not silently modify the operating system or install a privileged runtime.

### Build and install the development VSIX

```bash
cd extension
npm ci
npm run package
code --install-extension systemstudio-cis310.vsix
```

Run the install command from the student's local desktop, or use **Extensions: Install from VSIX…** in the desktop VS Code window. The extension is deliberately a local UI extension because Digital opens a native graphical window; a remote SSH extension host cannot install or display it.

Open the **SystemStudio CIS 310** activity-bar view and select **Install/Verify Digital**. The extension downloads Digital only after confirmation and verifies both pinned checksums maintained in [`digitalRelease.ts`](https://github.com/proywm/systemstudio-ai-senior-design/blob/HEAD/extension/src/core/digitalRelease.ts).

## Student workflow

1. Run **CIS 310: Check Environment**.
2. Run **CIS 310: Create Starter Workspace**, or open an instructor-provided workspace.
3. Open a `.dig` file.
4. Choose **Open With → SystemStudio Circuit Preview** for the integrated diagram view.
5. Use **Run tests** or VS Code Test Explorer for deterministic circuit evidence.
6. Use **Open in Digital** for graphical editing and interactive simulation.
7. Save in Digital, return to VS Code, refresh the preview, and rerun tests.

## Commands

| Command | Purpose |
|---|---|
| `CIS 310: Install/Verify Digital Simulator` | Downloads or repairs the pinned simulator installation |
| `CIS 310: Check Environment` | Reports Digital checksum, Java, and trust status |
| `CIS 310: Open Circuit in Digital` | Launches the native Digital GUI on a `.dig` file |
| `CIS 310: Run Digital Circuit Tests` | Runs embedded test cases with the official headless CLI |
| `CIS 310: Preview Digital Circuit` | Opens the in-editor SVG circuit preview |
| `CIS 310: Create Starter Workspace` | Creates a small verified example workspace |

## Where Digital is installed

Digital is stored under VS Code’s `ExtensionContext.globalStorageUri`, not in the course repository and not in a system-wide application directory. The extension keeps Digital configuration in the same managed area.

The exact path appears in **CIS 310: Check Environment** and the **SystemStudio CIS 310** output channel.

## Security and privacy

- Digital comes from a versioned HTTPS GitHub release URL.
- The extension verifies the ZIP and JAR SHA-256 digests.
- Processes use argument arrays with `shell: false`; workspace text never becomes a shell command.
- Simulation, SVG export, and tests require Workspace Trust.
- The Digital remote-control TCP server remains disabled by default.
- The extension sends no circuit, test, identity, or telemetry data to an AI or external service.
- Downloads and generated previews remain in extension-managed local storage.

## Development

```bash
npm ci
npm run check
```

Press `F5` from this folder in VS Code after running `npm run compile`, or install the packaged VSIX.

The automated check currently covers 13 unit tests plus bundling. A manual end-to-end smoke test has also verified safe extraction of the official Digital v0.31 ZIP, the pinned JAR checksum, the upstream half-adder testcase, and SVG export on Linux with Java 17. Classroom deployment still requires Windows/macOS and accessibility validation.

## Current limitations

- local desktop workspaces only; the Java GUI cannot open a remote filesystem path directly;
- Java must already be available or configured;
- only embedded Digital `Testcase` components are automatically discovered in Test Explorer;
- no AI coach, grading, LMS integration, or student-data collection in this MVP; and
- graphical editing occurs in the managed native Digital window, not inside a webview.

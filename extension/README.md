# SystemStudio CIS 310 VS Code Extension

This is the active Fall 2026 CIS 310 student extension. It gives students one VS Code entry point for self-paced pre-class open-book preparation, official author videos, short formative practice, local learning progress, the packaged syllabus, course calendar, Canvas routing, embedded course materials, Digital logic circuits, an embedded IA-32 assembly lab, a self-paced tutorial, a local FAQ chat, a U-M Maizey tutor handoff, and a Canvas pre-class question workflow.

The [Reading–Video–Practice Alignment Audit](CONTENT_ALIGNMENT_AUDIT.md) records how every readiness prompt and practice question was verified against exact book sections and actual video content.

**Remote SSH is not required.** The embedded circuit and assembly workbenches run in desktop or Remote SSH VS Code. Students need local desktop VS Code only for Digital’s separate full Swing editor; the course-scoped circuit editor, learning tools, and assembly machine remain inside VS Code.

## Honest circuit-integration boundary

Digital is a Java Swing/AWT desktop application, while a VS Code custom editor is an HTML/JavaScript webview. VS Code has no supported cross-platform mechanism for mounting a separate operating-system Swing window inside an editor tab. SystemStudio therefore uses two deliberately separate levels:

1. **Embedded Circuit Workbench:** original extension code for the CIS 310 one-bit subset—inputs, outputs, AND/OR/XOR/NOT, a manual clock, and D flip-flops. It builds, wires, drags, toggles, simulates, and saves Digital-compatible `.dig` files inside desktop or Remote SSH VS Code without Java.
2. **Verified Digital integration:** Digital v0.31 supplies the official SVG preview, embedded testcase runner, advanced components, buses, memories, subcircuits, HDL features, and full native editor. The extension installs and verifies this separate application; Java is required for these functions.

The embedded editor refuses to rewrite a file containing unsupported components, rotations, or gate shapes. It instead offers the full Digital editor, the read-only verified preview, or XML source. This prevents a simplified editor from silently damaging an advanced circuit. The full Digital window remains a managed companion rather than a falsely embedded or remote-streamed desktop.

## Assembly compatibility boundary

The **Embedded Assembly Lab** is original extension code: a bounded, source-level IA-32 teaching interpreter. Students select **Irvine32 Classroom (MASM)**, **NASM IA-32**, or **Auto-detect**; that choice controls source compatibility, not a platform-dependent installer. The Irvine32 profile recognizes the common wrappers used in CIS 310 (`.386`, `.model flat,stdcall`, `.stack`, `.data`, `.code`, `PROC`/`ENDP`, `INVOKE ExitProcess`, `EXIT`) and implements a documented set of common classroom calls such as `DumpRegs`, `ReadInt`, `ReadString`, `WriteInt`, `WriteString`, and `RandomRange`. It executes no native student code and needs no Docker, Visual Studio, assembler, linker, SDK, administrator access, or network connection.

It is not Visual Studio, `ml.exe`, the Irvine32 binary library, or full NASM. It does not emit PE/ELF objects, reproduce an OS ABI, load external binaries, or implement every instruction, directive, macro, x87, or SIMD feature. EIP uses synthetic teaching addresses rather than encoded instruction lengths. Activities requiring exact binaries, operating-system calls, external libraries, or unsupported syntax still need the instructor-approved native toolchain. See `assembly/IRVINE32_PROFILE.md` and `assembly/COMPATIBILITY.md` in a generated lab.

## Student installation

### Prerequisites

No Java installation is needed for the embedded circuit workbench or Embedded Assembly Lab. Install Java 8 or newer—Java 17 or 21 is recommended—when using Digital’s official preview/tests or full advanced editor. The extension checks Java but does not silently modify the operating system or install a privileged runtime.

The Embedded Assembly Lab has no additional prerequisite. Its engine is bundled in the VSIX and behaves the same way on Windows, Linux, macOS, and Remote SSH because it does not execute a host binary.

### Build and install the development VSIX

```bash
cd extension
npm ci
npm run package
code --install-extension systemstudio-cis310.vsix
```

Run the install command from the student's desktop, or use **Extensions: Install from VSIX…**. The embedded circuit editor, assembly machine, and learning tools also work in Remote SSH. Digital’s native editor can open remotely only when that host has a graphical display; otherwise use the embedded editor or reopen locally for advanced Digital features.

Open the **SystemStudio CIS 310** activity-bar view and select **Install/Verify Digital**. The extension downloads Digital only after confirmation and verifies both pinned checksums maintained in [`digitalRelease.ts`](https://github.com/proywm/cis310-systemstudio-course-materials/blob/main/extension/src/core/digitalRelease.ts).

## Student workflow

1. Open **Start Here** and complete the next pre-class module: read the focused open-book sections, watch the targeted author videos, then try three readiness questions. Each step is skippable.
2. Start or skip the guided tutorial; rerun it later from **Help and Tutorial**.
3. Open the packaged **Fall 2026 syllabus** and review any fields still marked for instructor confirmation.
4. Open the **Fall 2026 course calendar** to see all 27 Monday/Wednesday meetings; export all-day placeholders or enter a confirmed Canvas time for timed events.
5. Open [Fall 2026 Canvas](https://canvas.umd.umich.edu/courses/552144) to confirm the current task, deadline, class details, and required files.
6. Open **Lessons and Assignments** and select one of the 13 bundled presentation PDFs, three homework references, or three project references after completing the related reading.
7. Use **Learn and Practice** for the complete book/video map, a short topic session, a 10-question quiz, or review of due and saved questions. State confidence before seeing feedback, then use the explanation, visibly labeled mapped book/video focus, and related lecture.
8. Before opening the AI tutor, confirm the learning-coach boundary. Attempt ungraded practice first; for graded work, request a hint, analogous example, source, or critique of your own reasoning—not a final answer or submission artifact. Canvas controls assignment-specific AI permission.
9. Build the one-bit course components in the embedded workbench. Run **CIS 310: Check Environment** only when Digital’s verified preview/tests or advanced editor reports a tool failure.
10. Open **Hands-on Circuit and Assembly Labs**. For Lecture 2, predict all four one-bit additions, create the fresh half-adder circuit, build and connect Sum and Carry paths inside VS Code, toggle every row, and explain the evidence.
11. Continue with a mapped Boolean, selector, state, decoder, ALU-slice, or assembly trace as the related lecture reaches that concept. Guided checkmarks stay local and are not grades.
12. Create a starter workspace, a blank circuit, or an assignment-specific circuit. Existing work is never overwritten; keep guided practice separate from assignment work.
13. Predict one behavior, then use preview/tests or machine-state evidence before integrating a larger component.
14. Use **Full Digital** for buses, memories, subcircuits, HDL, or other components outside the embedded course subset.
15. Open the chat-style help bubble: use the local FAQ for routing, U-M Maizey in Canvas for a source-grounded conversational hint, or **Ask a Question Before Class** to prepare a named or Canvas-enabled anonymous discussion post.
16. Submit the required deliverables through Canvas and confirm that Canvas recorded the submission.

For assembly, select a mapped Hands-on Lab Center trace. It opens `AddTwo.asm`, `FlagsBranch.asm`, `LoopSum.asm`, `StackCall.asm`, or `ConsoleInput.asm` beside the embedded panel. Leave **Auto-detect** selected or use the lab's Irvine32 Classroom/NASM IA-32 profile. Predict first, then use **Build**, **Step**, **Run**, and **Rebuild / Reset** while inspecting registers, flags, stack, data, virtual-console input, output, EIP, and the execution trace. Read the two assembly guides before using a file that depends on a full native assembler or OS runtime.

Course guides and assignments open as rendered documents. Instructors and developers can use **Open With → Text Editor** when they intentionally need to inspect or edit the Markdown source.

## Learning Center

The Learning Center is a low-stakes study loop, not another graded course destination. A student can:

1. move through all 13 lecture modules using **Read → Watch → Try 3 questions**;
2. open focused chapters of David Tarnoff's *Computer Organization and Design Fundamentals* and the targeted official author videos needed for each lecture;
3. take a five-question recommended session, review due/saved items, choose one of six topics, or take a 10-question quiz;
4. make one choice at a time and record low, medium, or high confidence before submitting;
5. request a hint in practice mode, then read an explanation, a concise takeaway, and open the mapped book, video, or packaged lecture;
6. optionally record whether a miss came from the concept, a careless step, a guess, or a need for human help; and
7. revisit questions using a transparent local review schedule.

Practice mode reveals feedback after each response. Quiz mode withholds feedback until the session ends. Reading/video completion is self-reported. The dashboard reports questions encountered, practice accuracy, items due, practice days, and confidence mismatches such as a confident miss or a correct-but-uncertain answer. These are descriptive practice signals: the extension does not infer mastery, predict a course grade, rank students, or send progress to the instructor. Learning data stays in VS Code's local extension storage until the student resets it. Book/video links open official external sites with their own privacy practices.

See [LEARNING_DESIGN.md](LEARNING_DESIGN.md) for the usability audit, research basis, and explicit boundaries.

## Where Digital is installed

Digital is stored under VS Code’s `ExtensionContext.globalStorageUri`, not in the course repository and not in a system-wide application directory. The extension keeps Digital configuration in the same managed area.

The exact path appears in **CIS 310: Check Environment** and the **SystemStudio CIS 310** output channel.

## Security and privacy

- Digital comes from a versioned HTTPS GitHub release URL.
- The extension verifies the ZIP and JAR SHA-256 digests.
- Processes use argument arrays with `shell: false`; workspace text never becomes a shell command.
- Simulation, SVG export, and tests require Workspace Trust.
- Embedded assembly never starts a process or executes native student code. It uses a fresh 1 MiB in-memory model, a 10,000-instruction run limit, a 4,096-byte output-string limit, and source-line diagnostics.
- The engine has no filesystem, shell, process, or network instruction and remains available in a restricted workspace.
- The Digital remote-control TCP server remains disabled by default.
- The extension sends no circuit, test, identity, helper conversation, reading/video checkmark, practice history, confidence response, or telemetry data to an AI or external service.
- Reading/video checkmarks and practice history stay in VS Code extension storage, are used only for local recommendations and summaries, and can be reset from the Learning Center.
- Fixed open-book and author-video buttons open the official external ETSU/YouTube sources; those sites have their own privacy practices.
- Downloads and generated previews remain in extension-managed local storage.

## Current limitations

- the embedded circuit workbench intentionally supports a bounded one-bit component set and refuses to rewrite advanced `.dig` files; buses, memories, subcircuits, HDL, and unsupported rotations require Full Digital;
- the native Digital GUI cannot open on a Remote SSH host without a graphical display, while the embedded circuit workbench remains available;
- Java must already be available or configured only for Digital’s official preview/tests and full native editor;
- embedded assembly covers documented Irvine32 Classroom and NASM IA-32 teaching subsets rather than full MASM/NASM, binary generation, OS APIs, or arbitrary Irvine procedures/libraries;
- presentations are bundled as PDFs for offline use, but still require instructor content and accessibility review;
- packaged assignments are active study references; Canvas controls released questions, grading rules, deadlines, and submission;
- Learning Center checkmarks and results are local, self-reported formative evidence, not grades, mastery certification, accommodations, or a substitute for instructor feedback;
- the syllabus intentionally leaves class time/location, office hours, updated Irvine edition/access instructions, grading weights, detailed deadlines, and the final-exam slot for instructor confirmation rather than inferring them;
- only embedded Digital `Testcase` components are automatically discovered in Test Explorer;
- the local FAQ is a deterministic evidence-and-routing assistant; optional generative tutoring happens only after the student opens U-M Maizey in Canvas;
- the extension opens Canvas but does not read or submit Canvas coursework, and direct discussion posting would require an institution-approved Canvas OAuth/LTI integration; and
- supported one-bit graphical editing occurs inside VS Code; the complete Digital feature set remains in the managed native companion window.
